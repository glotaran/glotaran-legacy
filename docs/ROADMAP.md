# Roadmap

Glotaran 1.x has been superseded by [pyglotaran](https://github.com/glotaran/pyglotaran) for new work. This roadmap keeps the legacy desktop application buildable, installable, and usable, and ends with a 2.0 release that uses pyglotaran as its computational core.

| Release | Branch | NetBeans Platform | Java runtime | Computational core |
| --- | --- | --- | --- | --- |
| 1.5.3 | `maintenance/v1.5.x` | 8.0.2 (`RELEASE802`) | 8 | R + TIMP via Rserve, user-installed |
| 1.6.0 | `maintenance/v1.6.x` | Apache NetBeans 31 (`RELEASE310`) | 25 | R + TIMP via Rserve, user-installed |
| 1.7.0 | `maintenance/v1.7.x` | as 1.6 | 25 | R + TIMP via Rserve, provisioned by Glotaran |
| 2.0.0 | `main` | as 1.6 or later | 25 | pyglotaran, provisioned by Glotaran with bundled `uv` |

Each release builds on the previous one. The 1.x releases stay available for reproducing analyses made with TIMP; 2.0 uses a different engine, so its numerical results will differ from 1.x.

## Baseline (verified 2026-09-27)

Environment: Windows 11, Temurin JDK 8.0.492, Maven 3.9.14, R 4.6.1.

| Check | Result |
| --- | --- |
| `mvn -B -T 1C clean verify` | Success, 36 s wall clock; 509 warnings, 0 errors |
| `mvn -B -T 1C package -Pdeployment` | Success; `glotaran-app-1.5.2.zip` (49 MB), 119-file update site |
| Launch `application/target/glotaran/bin/glotaran64.exe` | Starts; all Glotaran modules enabled |
| Update center `https://glotaran.org/uc/1.5/stable/updates.xml` | Unreachable (`SocketException: Unexpected end of file from server`) |
| TIMP 1.13.6 and Rserve 1.8-19.1 from CRAN on R 4.6.1 | Windows binaries install and load |
| End-to-end analysis from the GUI | Not tested |

Relevant facts about the current code and ecosystem:

- `TIMPController/.../RserveProcessHelper.java` finds R through the Windows registry key `HKLM\Software\R-core\R` or a fixed list of Unix paths, then starts `R -e "library(Rserve);Rserve(...)"`.
- `CoreInterfaces/.../TimpControllerInterface.java` is the boundary between the GUI and the engine. Its callers are `AnalysisWorker`, `SimulationWorker`, and `SpecEditorTopCompNew`. One overload takes raw R strings (`initModelCalls`, `fitModelCall`) generated by `CoreAnalysis/.../support/InitModel.java` and `CoreSimulation/.../InitSimModel.java`.
- JAXB (`javax.xml.bind`) is used in 65 source files, 55 of them in `CoreModels`. It was removed from the JDK in Java 11.
- Apache NetBeans 31 was released on 2026-08-10. Its platform JARs are Java 21 bytecode (class file major version 65). The current NBM plugin is `org.apache.netbeans.utilities:nbm-maven-plugin` 14.5; this repository uses `org.codehaus.mojo:nbm-maven-plugin` 3.14.
- The `maintenance/v1.6.x-draft` branch (November 2023) contains a port to `RELEASE126` at version `1.6.0-SNAPSHOT`. The remote `maintenance/v1.6.x` branch is still at `1.5.2-SNAPSHOT` on `RELEASE802`.
- TIMP 1.13.6 (2022-12-12) is on CRAN. conda-forge has `r-base` 4.6.1 and `r-rserve`, but no `r-timp`.
- pyglotaran 0.7.4 is on PyPI and requires Python `>=3.10,<3.15`.

See [BUILD_AND_DISTRIBUTION.md](BUILD_AND_DISTRIBUTION.md) for the packaging, installer, and release setup these releases use.

## 1.5.3 — final RELEASE802 maintenance release

Goal: a public release of the current application that tells users about pyglotaran and where to find new releases of legacy Glotaran.

Version choice: the source was set to 1.5.2 by the Maven release-prepare commit `ace5cae`, but 1.5.2 was never officially released; no `v1.5.2` tag or GitHub release exists. Snapshot builds labelled 1.5.2 were handed to some users, so the release is 1.5.3 to avoid two different builds both called 1.5.2. The source is set to 1.5.3, including `glotaran.modules.specification.version`.

Scope:

1. Add a notice, shown at startup until dismissed, pointing to pyglotaran and to the GitHub Releases page of this repository. Store the dismissal in `NbPreferences` and add a Help menu entry that shows it again. Put it in an existing module (for example the `CoreMain` module installer); no new module.
2. Update every place where the version is set, as listed under "Branding and version numbers" in [BUILD_AND_DISTRIBUTION.md](BUILD_AND_DISTRIBUTION.md), including `glotaran.modules.specification.version` (still 1.5.1).
3. Decide what happens to the update center URL registered in `CoreAUC`. Publishing a 1.5.3 update site at `https://glotaran.org/uc/1.5/stable/` delivers the notice to existing 1.5.x installations. If glotaran.org cannot host it, leave the URL unchanged and rely on the website and README.
4. Rewrite the README "Latest releases" section to match this roadmap.
5. Document a tested R setup in the release notes: R 4.6.x, `install.packages(c("TIMP", "Rserve"))`.
6. Run one analysis end to end with the example data on Windows, and at least start the app on Linux and macOS.
7. CI: upload the portable ZIP as a workflow artifact, and add a tag-triggered workflow that creates the GitHub Release with the ZIP and its SHA-256.

Release artifacts: the portable ZIP is required. Native installers are optional: the NBI goal currently exits successfully without producing installers, and the macOS DMG path is unsigned and untested. Ship an installer only if it is built and launch-tested on its target OS.

Non-goals: dependency upgrades, Java or NetBeans upgrades, bundling Java or R.

## 1.6.0 — port to current Apache NetBeans Platform

Goal: the same feature set as 1.5.3 on Apache NetBeans 31 and a Java 25 runtime.

Approach:

1. Create `maintenance/v1.6.x` from the `v1.5.3` tag. Replace the existing remote branch of that name, which contains no 1.6 work, after confirming nothing on it is needed.
2. Port the relevant changes from `maintenance/v1.6.x-draft` (RELEASE126) forward, then move to `RELEASE310`.
3. Switch to `org.apache.netbeans.utilities:nbm-maven-plugin` 14.x and current Maven plugin versions; build with JDK 25.
4. Add JAXB as a library dependency (`javax.xml.bind` 2.3.x keeps the existing imports; Jakarta XML Binding 4 requires renaming packages in 65 files).
5. Resolve NetBeans artifacts from Maven Central and remove the RELEASE802 content from `repo/`. Keep `repo/` only for libraries that are not available from a public repository, and list them in `docs/MAVEN.md`.
6. Re-check the application module's cluster selection and exclusions against the current platform; module names and clusters changed between 8.0.2 and Apache NetBeans.
7. Bundle a Java 25 runtime per OS (set `jdkhome` in `glotaran.conf`) so users do not need a JDK. Use a different user directory (`.glotaran/1.6`).
8. Enable the `NbModuleSuite` smoke test in `application/` and run it in CI.

Acceptance: CI builds on Linux, Windows, and macOS; the app starts on all three; the example analysis produces the same results as 1.5.3 against the same R/TIMP installation.

Non-goals: UI redesign, refactoring beyond what the API changes require, new analysis features.

## 1.7.0 — self-provisioned R and TIMP

Goal: Glotaran installs and manages its own R, TIMP, and Rserve, without administrator rights and without the user running R.

Design:

- Add a runtime-provisioning service in `TIMPController` (or a new module if the code does not fit) with three states: not installed, installing, ready. An options panel shows the state, the R and package versions, and a "use my own R installation" override that keeps today's behaviour.
- Install into the Glotaran user directory, pinned to tested versions of R, TIMP, and Rserve. Install TIMP and Rserve from CRAN binaries into a private library and pass it to R via `R_LIBS`, so any existing user R library is not touched.
- Replace the registry and fixed-path lookup in `RserveProcessHelper` with the provisioned R path, falling back to the lookup only when the user selects their own R.

Provisioning options to evaluate before implementation:

| Option | Windows | macOS | Linux | Notes |
| --- | --- | --- | --- | --- |
| CRAN R installer, silent per-user install | yes | `.pkg` needs admin | no official binary | Different mechanism per OS |
| [rig](https://github.com/r-lib/rig) | yes | yes | yes | Installs system-wide; admin on macOS/Linux |
| conda-forge via `pixi` or `micromamba` | yes | yes | yes | User space, lock file; `r-base` and `r-rserve` available, TIMP installed from CRAN afterwards |

conda-forge is the likely choice because one mechanism covers all three platforms without admin rights. It must be verified that CRAN's TIMP dependencies (`fields`, `deSolve`, `minpack.lm`, `nnls`, and others) install into a conda-forge R on each OS.

This provisioning service is also the basis for 2.0, where the managed runtime becomes Python via `uv`.

Acceptance: on a clean Windows, macOS, and Linux user account with no R installed, the first analysis triggers provisioning and completes.

## 2.0.0 — pyglotaran as the computational core

Goal: the Glotaran GUI performs analyses with pyglotaran. R, TIMP, and Rserve are no longer used.

Design:

- Implement a pyglotaran controller behind the engine boundary. Because the current interface passes TIMP R strings, the boundary moves to the model level: `Tgm` model + datasets in, `TimpResultDataset` out. `InitModel` and `InitSimModel` become TIMP-specific and are removed with the R backend.
- Translate `Tgm` (the `CoreModels` JAXB model) to a pyglotaran model and parameter specification. Build a feature matrix of TIMP options against pyglotaran support (kinetic schemes, IRF and dispersion, coherent artefact, spectral constraints and relations, clp equalities, oscillations). The GUI disables options that pyglotaran does not support and says so.
- Run pyglotaran as a subprocess. Start with one process per analysis that exchanges files in a project work directory (model and parameter files, data in a format pyglotaran reads, results written by pyglotaran). Move to a long-lived process with a JSON protocol only if process start-up time is a measured problem.
- Bundle the `uv` binary per OS. On first use run `uv python install` and `uv sync` against a `pyproject.toml` and `uv.lock` shipped with the release, into the Glotaran user directory. Pin pyglotaran to a tested version. Provide an offline option that pre-populates the `uv` cache.
- Keep reading existing `.gta`/`.tgm` projects. Results saved by 1.x remain viewable.

Validation: rerun the example analyses and a set of real 1.x projects with both engines, and document parameter and residual differences. Differences are expected and must be explained in the release notes.

Non-goals: reimplementing pyglotaran features in Java; supporting TIMP and pyglotaran side by side in 2.0 (users who need TIMP stay on 1.7).

## Open decisions

- 1.5.3 versus tagging the existing commit as 1.5.2.
- Whether glotaran.org can host the 1.5 update center again.
- Whether 1.7 is worth its cost when 2.0 removes R; if 2.0 is the priority, build the provisioning service directly for `uv` and skip 1.7.
- Code signing for Windows and macOS installers (certificates, notarization).
- Supported platforms for bundled runtimes (Windows x64, macOS arm64 and x64, Linux x64).
